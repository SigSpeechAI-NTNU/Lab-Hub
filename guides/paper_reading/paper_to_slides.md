# 論文報告：把一篇論文變成投影片與講稿（v2.2，2026-10-08）

> 位置：貫穿各站。group meeting 的論文報告每週一人、partner 組內輪流（第 5 站 §7），一篇 20 分鐘。
> 這一站的目的：報告一篇論文，讓聽的人知道它做了什麼、**方法怎麼訓練怎麼推論**、數字可不可信、對我們有什麼用。重點是方法——你要能拿一個具體的輸入，從頭走到尾講完。
> 流程：**PDF 餵 AI → AI 產生 Quarto 投影片與講稿的草稿 → 你帶著草稿讀論文、逐頁核對、和 AI 對話修正 → 三頁自己寫**。
> 產出：一份 Quarto 投影片（`.qmd` 與 render 出的 `.html`，13 頁上下，每頁有講稿）＋一頁核對紀錄（Markdown，放自己 repo 的 `notes/papers/`，檔名同投影片：`〔會議〕_〔年份〕_〔第一作者的姓〕.md`）。
> 語言：**投影片本體一律英文**（標題、圖說、表格、條列），**講稿用繁體中文**。進度報告的投影片可以中文，論文報告不行——它是練習用英文講方法。
> 鐵律：**第 7 頁走線的講稿、第 12 頁我的判斷、第 13 頁啟發，AI 不生，你自己寫。** 這三頁是你讀懂與否的試金石；其餘十頁 AI 生草稿、你核對。

## 0. 這一站怎麼接前後

- 論文從哪來：Round 1 的入門必讀、Round 2 §2 的盤點、Table 1 的 baseline 原論文、教授指定。原則：和 partner 組的議題相關
- 輸出到 1b：第 13 頁「對我的題目的啟發」要說這篇能不能變成一張 idea card（來源 1 文獻 gap、4 跨領域移植、5 挑戰前提）
- 輸出到第 2 站：論文的實驗設定是你檢查「公平比較」的練習；它的主表是你 Table 1 的參考
- 投影片機制和第 5 站一樣用 Quarto，差異見 §4

## 1. 流程：五步

| 步 | 做什麼 | 花多久 |
|---|---|---|
| 1 餵 | 把 PDF 給 AI，貼 §4.3 的指令，拿到 `.qmd` 草稿；render 成 html 看一遍 | 30 分鐘 |
| 2 第一遍讀 | 對著草稿讀論文的摘要、所有圖表、結論；核對第 1–3 頁與第 9–11 頁的每個數字（§5） | 1 小時 |
| 3 第二遍讀 | 讀方法節，對著第 4–6 頁的架構圖逐個模組、逐個符號核對；分清楚訓練與推論；**自己寫第 7 頁走線的講稿** | 2–3 小時 |
| 4 修 | 核對有錯的，和 AI 對話修（§4.4）；**自己寫第 12、13 頁** | 1 小時 |
| 5 收 | 填核對紀錄（§2）、render、commit、演講稿念一遍計時 | 30 分鐘 |

第 3 步是重點。AI 生的走線講稿常常很像一回事但形狀、query 的來源、訓練與推論的差異是錯的——這正是你自己寫那一頁的原因。卡住的公式、符號先問 AI（§6），AI 解釋完回論文對一次；還是不懂就記下來，報告時直接說「這裡我沒完全懂」，比裝懂好。

## 2. 核對紀錄

一頁 Markdown，`notes/papers/〔會議〕_〔年份〕_〔第一作者的姓〕.md`（例：`icassp_2026_lee.md`；arXiv 預印本用 `arxiv_2026_lee`）。它是你的核對清單，也是之後回頭看這篇論文時的摘要。每格標來源：`AI` 生的、`✓` 我核對過、`我` 自己寫的。

```markdown
# 〔論文標題〕
〔作者、會議／期刊、年份、URL〕 讀的日期：〔　〕

| 格 | 內容 | 來源 |
|---|---|---|
| 一句話 | 在〔任務〕上，〔方法〕讓〔主指標〕在〔資料集〕從〔A〕到〔B〕，代價是〔　〕 | AI→✓（對回表〔N〕） |
| 背景 | 〔原本的 pipeline，2–3 句〕 | |
| 痛點 | 〔一個具體的失敗例子〕 | |
| 架構 | 輸入〔　〕輸出〔　〕；模組〔　〕；新加的是〔　〕 | AI→✓（對回 §〔　〕） |
| 訓練 | 資料〔　〕損失〔　〕更新〔　〕凍結〔　〕 | |
| 推論 | 和訓練哪裡不同〔　〕 | |
| 走線 | 〔例子〕→〔模組 1：變成什麼〕→ ⋯ → 輸出 | **我** |
| 物理意義 | 新成分拿掉會怎樣〔　〕；位置〔　〕；成本〔　〕 | |
| 設定 | 資料集〔　〕指標〔　〕baseline〔　〕 | |
| 公平嗎 | 同 backbone？〔　〕同資料？〔　〕baseline 重跑還是引用？〔　〕seed？〔　〕 | ✓（翻實驗節） |
| 主結果 | 〔3–5 列〕；贏多少、哪裡贏最多、哪裡沒贏 | AI→✓（對回表〔N〕） |
| 消融 | 拿掉新成分掉多少（對回物理意義第一題） | |
| 賣點圖 | 〔哪張圖、它想證明什麼〕 | |

| 沒把握 | 〔　〕 | |

## 修正紀錄（和 AI 對話改了什麼）
- 第〔N〕頁：AI 寫〔　〕，論文 §〔　〕寫的是〔　〕，已改
```

「修正紀錄」那段要留：它告訴教授你核對到什麼程度，也是你下次判斷「AI 在這類論文上常錯哪裡」的材料。

## 3. 投影片：13 頁上下

每頁都有講稿。20 分鐘，方法佔 8 分鐘。頁標題固定用下表的英文；投影片上的文字全英文，講稿中文。

| 頁 | 標題 | 內容 | 講稿 | 誰寫 | 分鐘 |
|---|---|---|---|---|---|
| 1 | One-sentence claim | 核對紀錄的那一句；作者、會議、年份 | 為什麼挑這篇 | AI→核對 | 1 |
| 2 | Background | 原本的 pipeline，示意圖 | 原本怎麼做 | AI→核對 | 1.5 |
| 3 | Pain point | 在背景圖上標出壞掉的位置；一個具體失敗例子 | 這個例子為什麼錯 | AI→核對 | 1.5 |
| 4 | Architecture | 架構圖；新成分用不同框標出 | 輸入、輸出、每個模組一句 | AI→核對 | 2 |
| 5 | Training | 架構圖加損失與梯度流向；凍結的塗灰 | 資料從哪來、算什麼損失、更新什麼 | AI→核對 | 2 |
| 6 | Inference | 同一張架構圖拿掉訓練才有的東西 | 和訓練哪裡不同 | AI→核對 | 1.5 |
| 7 | Trace one example | 架構圖上標一個具體例子的中間狀態 | 這個例子經過每個模組變成什麼 | **我** | 2 |
| 8 | Why it works | 新成分拿掉會怎樣；位置；成本 | 你的推理，之後和消融表對 | AI→核對 | 0.5 |
| 9 | Setup and fairness | 資料集、指標、baseline；公平性四問的答案 | 哪裡不公平 | AI→核對 | 1.5 |
| 10 | Main results | 主表 3–5 列，關鍵數字加粗 | 贏多少、哪裡贏最多、哪裡沒贏 | AI→核對 | 2 |
| 11 | Ablation and key figure | 消融表幾列；賣點圖一張 | 消融有沒有驗證第 8 頁的推理；圖想證明什麼 | AI→核對 | 1.5 |
| 12 | My assessment | 最強、最弱、審稿人會問 | — | **我** | 1.5 |
| 13 | Takeaways for my work | 能借什麼；要不要變 card | — | **我** | 1 |

### 圖的規則

- 方法的三張圖（4、5、6 頁）用**同一張架構圖**改三次，不要三張長得不一樣的圖
- **論文有架構圖**：可以截圖，但必須加自己的標註——框出新成分、用箭頭標訓練與推論路徑、標走線例子的中間狀態。沒加標註的截圖不算
- **論文沒有架構圖**：§4.3 的指令本來就會用 Mermaid 畫三個版本；畫得不對就把方法節原文貼給 AI、照 §4.3 第 4–6 頁的規則重畫一次，畫完對回論文的方法節，每個模組和符號都要對得上
- 實驗圖直接截論文的，標出要看的地方
- 每張圖標來源：「圖取自原論文 Fig. 2，標註為本人所加」

### 走線怎麼講

這是判斷你懂不懂的那一頁，所以講稿自己寫。拿論文自己的例子（通常在 introduction 或 figure 裡），或自己編一個最小的：一句話、一個 list、一個 batch。對每個模組講三件事：進去是什麼、出來是什麼、形狀或內容怎麼變。講得出「這句話進 encoder 之後是 T×D 的矩陣，biasing module 對它做 cross-attention，query 是 decoder 的 hidden state」就是懂了；只念模組名稱就是沒懂。

## 4. 用 Quarto 做

機制同第 5 站 §4（qmd → `quarto render` → html commit 進 `reports/`）。這裡補論文報告專用的部分。

### 4.1 檔案與 YAML

```
reports/
  icassp_2026_lee.qmd     〔會議〕_〔年份〕_〔第一作者的姓〕，全小寫
  icassp_2026_lee.html
  figs/                 截圖與自己畫的圖
```

YAML 固定用這段（1280×800 是以筆電螢幕為準的畫布；`include-after-body` 那段讓講稿裡的 LaTeX 在 presenter view 正常顯示——沒有它，presenter view 會把公式印兩次）：

```yaml
---
title: "〔論文短名〕"
subtitle: "〔作者，會議 年份〕"
author: "〔名字〕"
date: "〔YYYY-MM-DD〕"
format:
  revealjs:
    width: 1280
    height: 800
    margin: 0.04
    slide-number: c/t
    center: false
    navigation-mode: linear
    html-math-method:
      method: katex
    include-after-body:
      - text: |
          <script>
          // 講稿（aside.notes）裡的數學只輸出 MathML，避免 presenter view 重複顯示
          (function () {
            var items = [];
            document.querySelectorAll('aside.notes .math').forEach(function (el) {
              items.push({ el: el, tex: el.textContent, display: el.classList.contains('display') });
              el.classList.remove('math');
            });
            document.addEventListener('DOMContentLoaded', function () {
              items.forEach(function (it) {
                katex.render(it.tex, it.el, { displayMode: it.display, output: 'mathml', throwOnError: false });
              });
            });
          })();
          </script>
---
```

qmd 裡放圖：`![架構圖，取自原論文 Fig. 2，標註為本人所加](figs/arch.png)`。

### 4.2 講稿的格式

每一張 `##` 內容頁一段 `::: {.notes}`，固定兩塊：

```markdown
::: {.notes}
**【講述】**（約 N 分鐘）

可以直接照著念的口語段落。第一人稱。投影片上的每個數字、每個符號、每個模組都要講到它是什麼、從哪來。

**【提示】**

- 可能被問什麼、我打算怎麼答
- 我沒把握的地方（直接寫「這裡我不確定」）
- 這一頁的數字出處：論文表〔N〕、§〔　〕
:::
```

`**【提示】**` 後面**一定要空一行**，不然清單會被併成一段文字。講稿裡的數學用 `$…$`，符號和投影片本體逐字一致。

   邊上標資料的形狀（例 T×D）；節點標籤不含括號、引號、斜線
5  訓練（## Training）：同一張架構圖，加損失節點與梯度流向的邊；凍結的模組 style 填灰（fill:#ddd）；下方三行：資料從哪來、損失是什麼、更新哪些參數
6  推論（## Inference）：同一張架構圖，拿掉訓練才有的節點；下方一行：和訓練哪裡不同（teacher forcing／自回歸、beam search、哪些模組推論時不用）
7  走線（## Trace one example）：只放標題與一行〔〕，其餘留空，講稿整段留〔〕。這頁我自己寫
8  物理意義（## Why it works）：三行——新成分拿掉會怎樣、為什麼放這個位置、參數量或計算量佔多少；論文沒寫的標「論文未說明」
9  設定與公平性（## Setup and fairness）：兩欄表——資料集、指標、baseline；然後四問各一行：同 backbone？同資料？baseline 重跑還是引用？多 seed？論文沒寫的寫「論文未說明」
10 主結果（## Main results）：主表只留 3–5 列（baseline 與提案方法），關鍵數字加粗；表格下方註明「取自論文表 N」
11 消融與賣點圖（## Ablation and key figure）：消融表幾列（拿掉新成分掉多少）；賣點圖用 ![取自原論文 Fig. N](figs/selling.png) 佔位，下方一行它想證明什麼；最後一行「沒報的東西：〔推論速度／其他資料集／seed〕」

13 對我的題目的啟發（## Takeaways for my work）：只放兩個項目的標題（What to borrow／Idea card?），內容留〔〕，講稿留〔〕。這頁我自己寫

### 4.4 和 AI 對話修正

核對到錯的地方，這樣問才改得準：

- **指出位置與依據**：「第 5 頁講稿說損失是 CTC，論文 §3.2 第二段寫的是 CTC 與 attention 的加權和，權重 0.3，請改第 5 頁的講稿與圖」
- **一次改一處**，改完看一次再改下一處；一次丟十個錯 AI 會漏
- **不要說「這頁怪怪的」**——它會重寫整頁，連對的也改掉
- **形狀與符號對不上時，把論文的符號表貼給它**：「論文定義 H 是 T×D，你寫成 D×T」
- AI 改完你再對一次論文。改了三次還不對的，自己改 qmd，不要再問

每改一處，在核對紀錄的「修正紀錄」加一行。

## 5. 核對清單

| 頁 | 對什麼 | 對回論文哪裡 |
|---|---|---|
| 1 | A、B 兩個數字 | 主表的表號與列 |
| 2–3 | 背景的 pipeline、失敗例子 | introduction 或 related work；例子要論文有的 |
| 4 | 每個節點 | 方法節的段落或公式編號；對不到的刪掉 |
| 5 | 損失、更新與凍結的參數 | 方法節的訓練小節或實驗設定 |
| 6 | 推論與訓練的差異 | 方法節或實驗設定；論文沒寫就標「論文未說明」 |
| 7 | 走線的每個形狀 | 符號表；論文沒寫的寫「論文未明說，我的推測」 |
| 8 | 拿掉會怎樣 | 之後和第 11 頁消融表對 |
| 9 | 公平性四問 | 實驗設定節；找不到也是答案 |
| 10–11 | 每個數字、每張圖 | 表號、圖號 |

全部對完才算第 2 步做完。

## 6. AI 怎麼用

可以：
- 生 13 頁的草稿（§4.3）
- 解釋看不懂的段落、公式、符號；解釋完回論文對一次
- 畫架構圖草稿；改錯（§4.4）
- 問「這個方法和〔另一篇〕差在哪」當第二意見，但答案要自己驗證

不可以：
- 讓 AI 寫第 7、12、13 頁。指令裡已經規定留空；它若還是寫了，刪掉重寫
- 把 AI 的解釋當成論文說的；論文說的以論文為準
- 跳過第 5 節的核對直接報告。草稿通順不代表正確，AI 最常錯的正是形狀、損失的組合、訓練與推論的差異

## 7. 講的時候

- 方法 8 分鐘，走線一定講，就算要砍別的
- 數字只講加粗的；一張表不要逐格念
- 看不懂的地方直接說「這裡我沒完全懂，我的理解是⋯」。教授和 partner 可能知道
- 第 12 頁的「審稿人會問」要是真的問題，不是「資料集可以再多」這種萬用句
- 20 分鐘到就停，討論另計

## 8. 示例

> **示例，內容虛構。** 延續 contextual biasing STT；示範第 7 頁走線的講稿——這一頁要你自己寫，長這樣。

```
**【講述】**（約 2 分鐘）

我拿一句話走一遍。音檔是「please call Hsin-Yi」，biasing list 是三個詞：Hsin-Yi、Shin-Yi、Cindy。
音檔先進 encoder，切成 T 個 frame，出來是 T×D 的矩陣，每一列是一個 frame 的表示。
list 裡三個詞各編成一個 D 維向量，所以 biasing encoder 的輸出是 3×D。
decoder 走到要輸出人名那一步時，它的 hidden state 當 query，對那 3×D 做 attention，
得到一個 D 維的 context 向量——「偏向」就發生在這裡。
這個 context 和原本的 decoder 輸出合併，再過 softmax，Hsin-Yi 的機率被拉高，輸出就是「please call Hsin-Yi」。
訓練時 list 是從該句的參考文字抽出真實人名再混入干擾詞；推論時 list 由使用者給，decoder 是自回歸的，沒有 teacher forcing。

**【提示】**

- 可能被問：干擾詞怎麼抽？論文 §3.3：從訓練集的詞表隨機抽，比例 1:10
- 我不確定：合併是相加還是 concat 再投影，論文 §3.2 寫得不清楚，我的推測是 concat
```

## 9. 淺讀：每週 2 篇、每篇 5 行

深讀（上面那套）每三週一次；**淺讀每週 2 篇**，不做投影片，只在 `notes/papers/reading_log.md` 記 5 行：

```markdown
## 〔YYMMDD〕 〔會議_年份_姓〕 〔標題〕 〔URL〕
- 主張：在〔任務〕上〔方法〕讓〔指標〕從 A 到 B
- 動了哪一格：〔新成分／架構／學習方式／損失〕
- 和我的題目的關係：〔可借／是 baseline／無關但有趣〕
- 值得深讀？〔是／否，一句理由〕
```

來源：Round 2 §2 的盤點清單、Scholar alert 送來的、partner 推薦的。半年一百篇淺讀，是「想法越來越實際」真正的來源；深讀訓練的是講清楚，淺讀累積的是品味。進度報告第 8 頁多一行「本週讀了：〔2 篇的短名〕」。

## 10. 審稿預測練習（每三次論文報告輪一次）

讀接受的論文只學得到「好的長什麼樣」，學不到「為什麼被拒」。ICLR 的審稿在 OpenReview 全公開，是免費的教材。每三次論文報告，輪到的人改做這個：

1. 到 OpenReview 挑一篇同領域、**有完整審稿**的 ICLR 投稿（接受或拒絕都可以），只看論文不看審稿
2. 照上面 13 頁做一份**精簡版**（1、4、9、10、12 頁即可，8 分鐘）
3. 第 12 頁改成三行預測：會不會收、最大的問題是什麼、平均分數大約幾分
4. 報完當場開審稿，對答案：你抓到的問題審稿人有沒有提？審稿人提的你有沒有漏？
5. 把「漏掉的那一類問題」記進 `reading_log.md` 最上面的一段「我容易漏的」

半年六次之後，你對「什麼叫貢獻不夠」的感覺會比讀三十篇接受論文來得快。
