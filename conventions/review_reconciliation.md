# 審稿對帳：審稿意見回來之後（v1，2026-10-08）

> 什麼時候做：每次論文的審稿意見回來，不論收或拒，**讀完意見的 48 小時內**，在改稿或 rebuttal 之前。
> 為什麼：審稿意見是整個 lab 最貴的教材，一年只有兩三次。不對帳，它只會變成「這個審稿人不懂」的情緒。
> 產出：一張表，放自己 repo 的 `notes/reviews_〔會議〕_〔年份〕.md`；一行「我漏的那一類」回填 `reading_log.md` 最上面。

## 怎麼做

1. 把每一條審稿意見拆成一列（一個審稿人通常 3–8 條）
2. 每條對回第 2 站的決策紀錄：它打到的是哪一格——baseline 選擇、資料集、公平比較、貢獻主張、分析、寫作
3. 填「當時想到了嗎」：
   - **想到了，決定不做**：寫當時的理由；現在看理由站得住嗎
   - **想到了，沒做完**：時程問題，記下來給下次的 one-pager
   - **沒想到**：這是重點——是哪一類盲點？文獻（prior work 沒查到）、方法（副作用沒想）、評測（指標或資料集不夠）、主張（contribution 講過頭）、寫作（審稿人看不懂）
4. 統計「沒想到」裡最多的那一類，寫一句話進 `reading_log.md` 的「我容易漏的」
5. 在下次 group meeting 用 5 分鐘報這張表，不報論文本身

## 表格

```markdown
# 審稿對帳：〔論文短名〕 〔會議 年份〕 結果：〔收／拒／分數〕

| # | 審稿人 | 意見（一句話摘要） | 打到決策紀錄哪一格 | 當時想到了嗎 | 類別 | 下次怎麼避免 |
|---|---|---|---|---|---|---|
| 1 | R1 | | | 想到決定不做／想到沒做完／沒想到 | 文獻／方法／評測／主張／寫作 | |

## 「沒想到」最多的一類：〔　〕
## 回填 reading_log「我容易漏的」：〔一句話〕
## 審稿人誤讀的（不是我們的錯，但表示哪裡寫不清楚）：〔　〕
```

最後一列很重要：審稿人「誤讀」在作者眼裡是審稿人的問題，在下一篇論文裡是寫作的問題。

## 和其他站的關係

- 對回第 2 站的決策紀錄：所以決策紀錄要留著，不要投稿後就丟
- 「我容易漏的」累積在論文報告教材 §9 的 reading_log，和審稿預測練習（§10）用同一段
- 教授那邊：這張表教授會看，用來調整自己挑 card 的標準；partner 也看，同一類盲點通常整組都有
